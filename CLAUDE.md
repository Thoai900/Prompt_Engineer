# PromptBuilder — hướng dẫn cho AI agent

Ứng dụng web xây dựng & tối ưu prompt (React 19 + Vite + TypeScript, Firebase, deploy Vercel).

## Kiến trúc

- **Frontend**: React 19, Vite, Tailwind v4, `motion`, `lucide-react`. Vào từ `src/main.tsx` → `src/App.tsx`.
- **Điều hướng**: KHÔNG dùng router lib — `activeTab` đồng bộ với `window.location.hash` (`#builder`, `#lab`…) trong App.tsx. Deep-link phụ dùng query-param (`?t=`, `?app=`) đọc trong tab tương ứng, không đụng App.tsx.
- **Nhóm điều hướng**: `src/utils/navGroups.ts` (thuần) gom tab thành 4 nhóm Tạo/Thư viện/Thử nghiệm/Học — sidebar desktop có tiêu đề nhóm; mobile có thanh tab đáy (4 nhóm + "Thêm") và hàng tab con. Thêm tab mới thì nhớ thêm vào một nhóm (test `navGroups.test.ts` bắt lỗi thiếu).
- **Tab**: Home (eager) + các tab lazy: Studio, Builder, ProjectChain, **Thư viện**, Learn, **Lab**. Tab mount-khi-mở, giữ nguyên state (`visitedTabs`). Tab đã gỡ được chuyển hướng qua `resolveLegacyTab` trong `navGroups.ts`: `#enhancer` → Studio "Tăng cường nhanh" `?studio=quick`; `#aifuture` → Learn bản tin `?learn=news`; `#rulesskills` → `?lib=rules#library`; `#utilitybelt` → `?lib=configs#library`.
- **Thư viện** (`src/components/library/LibraryHub.tsx`, spec `docs/superpowers/specs/2026-11-18-unified-library-design.md`): một tab gộp Mẫu prompt (`TemplatesView`) · Rule/Skill (`RulesSkillsView` + `SkillsPanel`) · LLM Config (`ConfigsView`). Bộ chọn loại ghi URL `?lib=<kind>&id=<id>`; mở từ nơi khác bằng `openLibrary(kind, id?)` (`src/services/libraryNav.ts`). Ô tìm chung dùng `globalSearch.ts` (cùng nguồn Command Palette, thêm mẫu dựng sẵn/cộng đồng); gõ là chuyển sang "Tất cả". `LibraryExplorer` + `AuthoringWizard` chỉ gắn MỘT lần ở hub; nhập/tạo xong phát `notifyLibraryChanged(kind)` (sự kiện `pb:library-changed`) để view đọc lại. View đã mở giữ mounted (ẩn CSS). Gợi ý gõ nhanh / sao lưu / thống kê → `components/common/SettingsModal.tsx` (nút Cài đặt ở chân sidebar, menu mobile, Command Palette).
- **Lab** (`src/components/tabs/LabTab.tsx`): trung tâm "sức mạnh AI" 4 chế độ, mỗi chế độ một panel trong `src/components/lab/`:
  Bake-off (so tài model) · Auto-Optimizer (tối ưu prompt tiến hoá, chạy backend) · Prompt Health (CI cho prompt) · Độ ổn định (Prompt Profiler: chạy 1 prompt N lần trên ≤ 3 model, đo nhất quán/định dạng/độ dài/độ trễ/chi phí → Ổn định/Dao động/Giòn; logic thuần `src/utils/profiler.ts`) · Cá nhân hoá (taste model). Tab khác gửi prompt sang Bake-off/Optimizer qua `sendToLab()` (`src/services/labSeed.ts`, sessionStorage + sự kiện `pb:lab-seed`).
  Đã chuyển đi: Gia sư → Learn (`src/components/learn/TutorPanel.tsx`, mở từ PersonalGuide); Chain→App → Project Chain (`src/components/project-chain/AppPanel.tsx`, nút "Chạy như App"; link `?app=<id>#lab` cũ chuyển hướng về `#projectchain`).
  **Prompt Flywheel** (spec `docs/superpowers/specs/2026-11-18-prompt-flywheel-versioning-design.md`): Health suite có lịch sử revision gắn điểm (`src/utils/promptRevisions.ts`, thuần), banner tối ưu theo test trượt (`api/optimize.ts` nhận `tests[]`), và phản hồi 👍/👎 từ Shared App → hộp phản hồi → "Biến thành test" (`src/utils/feedbackUtils.ts`, `src/services/feedbackService.ts`). Test có `vars` = giá trị `{{biến}}` điền vào prompt mẫu trước khi chạy (cả ở `api/health-cron.ts`).
- **Vòng chất lượng** (spec `docs/superpowers/specs/2026-11-18-quality-loop-design.md`, đã GỘP vào Prompt Flywheel ở trên): template đã lưu → Prompt Health qua `sendToLab('health', text, {templateId, templateTitle})` (mở suite có `source.kind='template'`, chưa có thì tạo + AI soạn test `draftHealthTests`); nút "Soạn test bằng AI" ở mọi suite; tối ưu theo test trượt là banner Prompt Git (`OptimizeSuggestion`); khi phiên bản hiện hành khác template nguồn CỦA TÔI → `SaveAsVersionPanel` chia lại khối (`splitPromptIntoBlocks`, giữ câu chữ), xem diff, lưu thành phiên bản mới của CÙNG template rồi ghi revision `source-sync`. Lối vào: dải "Sức khoẻ prompt" trong `PromptDetailModal` (template của tôi) và nút "Kiểm thử chất lượng" ở bước Hoàn tất của Studio. Hàm thuần ở `src/utils/healthUtils.ts`. Chain → App mở suite qua `sendToLab('health', '', {suiteId})`.
- **Lịch sử phiên bản template** (H2, `src/utils/templateVersionUtils.ts`): App chụp bản cũ vào `versions` khi lưu đè CÙNG id. Builder: template của tôi (`canUpdateTemplate`) mặc định "Cập nhật" (giữ id) thay vì tạo bản mới; nút Lịch sử mở `VersionHistoryList` (`src/components/common/`, dùng chung với `PromptDetailModal`) để xem diff so với trình soạn và đưa bản cũ vào trình soạn. `usePromptBlocks` nạp lại mỗi khi App truyền template VỪA MỞ (object mới, kể cả cùng id) — đường "Khôi phục" từ Thư viện dựa vào điều này.
- **Prompt Inspector** (`src/components/common/PromptInspector.tsx`): chỗ "soi" prompt dùng chung — token/chi phí (`PromptMeter`) + linter AI (`lintPrompt`) + lối tắt "So tài model"/"Tối ưu" sang Lab. Gắn ở Builder, Prompt Graph (tab Prompt), Auto-Optimizer. Danh sách lỗi dùng chung `LintIssueList` (cả bước Kiểm tra của Studio); hàm thuần ở `src/utils/lintIssues.ts`. Linter không còn là chế độ riêng của Lab.
- **Project Chain v3 = "Prompt Graph"** (node-graph kiểu Blender trên `@xyflow/react`): 1 node Prompt Gốc (compiler — nội dung lõi TUỲ CHỌN, có cổng `Nhiệm vụ` để swap Task Node) với các cổng input đặt tên, node thuộc tính kéo dây cắm vào, bật/tắt (mute), prompt cuối lắp ráp realtime. 5 dạng node (`nodeType`): `text` · `preset` (Modifier dropdown/slider — thư viện `src/utils/graphPresets.ts`) · `fewshot` (cặp Input→Output) · `web` (cào URL qua `api/fetch-url.ts`, cache snapshot vào node — compile KHÔNG fetch) · `group` (Bundle: gom nhiều node thành 1 card, mỗi thành viên tự vào đúng cổng, KHÔNG cần dây; template nhiều block import vào sẽ nở thành group). Panel Chạy thử có vòng tự sửa lỗi 0–3 (self-correction loop — chiến lược THỰC THI, không phải node). Logic thuần ở `src/utils/graphCompile.ts` (compile/layout/chống chu trình/renderNodeText) + `graphMigration.ts` (migrate v2→v3, backup localStorage); UI ở `src/components/project-chain/` (GraphWorkspace là orchestrator). Cú pháp biến DUY NHẤT `{{ten_bien}}` — các cú pháp `{{output_N}}`/`{{parent.output}}` đã khai tử; `chainUtils.ts` chỉ còn đường tương thích cho Shared App legacy.
- **Thư viện năng lực AI** (`src/components/library-explorer/`): modal khám phá + nhập skill/rule/persona từ GitHub. Lớp `CatalogSource` (`src/services/catalogService.ts`) — đợt 1 `StaticCatalogSource` đọc manifest `src/data/skillCatalog.ts`, tải raw on-demand qua `api/github.ts`; logic parse/route thuần ở `src/utils/skillCatalog.ts`. Skill nhập về là `AiSkill.kind='document'`. Mở từ nút "Khám phá GitHub" của tab Thư viện (LibraryHub); import route theo `category`. **Đợt 2**: chế độ "Tìm GitHub" live (repo search → duyệt file) qua `api/github.ts` action `search`/`tree` (cần env `GITHUB_TOKEN`); suy loại file `src/utils/repoInference.ts`; câu lệnh cài skill cho agent `src/utils/agentInstall.ts`; trích file repo làm nền Rule/LLM Config (`routeImportAs`/`entryToProfileContext`). **Đợt 2.1**: card repo giàu thông tin (`RepoCard`: avatar/sao/ngôn ngữ/topic/cập nhật — `search` map thêm các trường vào `RepoHit`) + panel lệnh cấp REPO khi mở repo chưa chọn file (`RepoCommandsPanel`): `buildRepoCommands()` sinh lệnh tải TOÀN BỘ repo dùng chung (`git clone`/`degit`, để riêng) + mỗi agent một lệnh terminal + prompt "tự tải & kích hoạt".
- **Authoring wizard** (`src/components/authoring/AuthoringWizard.tsx`): nút "✨ Tạo bằng AI" ở đầu tab Thư viện (LibraryHub, mặc định theo loại đang xem) → modal mô tả-1-câu → `aiService.draft{Skill,Rule,Profile}FromBrief` (JSON) → review + lint (`src/utils/authoringLint.ts`, thuần) → lưu qua `persistImport`. Xuất đa định dạng `src/utils/exporters.ts` (SKILL.md/.cursorrules/AGENTS.md/CLAUDE.md, thuần) — dùng trong wizard và dropdown xuất của editor Rule.
- **Preset theo ngành**: preset built-in gắn `domain?` (rules/skills ở `src/presets.ts`, config ở `src/data/llmConfigPresets.ts`). Lọc bằng `DomainChips` + `filterByDomain`/`listDomains` (`src/utils/presetFilter.ts`, thuần) ở sidebar từng loại trong tab Thư viện và trong kết quả tìm kiếm chung. Nhóm chuyên môn cao (pháp lý/tài chính) có câu disclaimer trong nội dung.
- **Rule/Skill custom**: MỘT nguồn qua `src/services/collectionStore.ts` (`useRules()`/`useSkills()`, `rulesStore`/`skillsStore.save|remove`) — Firestore realtime khi đăng nhập, localStorage khi là khách, tự đẩy dữ liệu khách lên khi đăng nhập. KHÔNG đọc/ghi thẳng `custom_rules`/`custom_skills`.
- **State chung**: `src/context/WorkspaceContext.tsx` = nguồn chân lý cho user/auth/API keys/workspaces/personas (đồng bộ Firestore hoặc localStorage). Đừng thêm mảng workspace/persona hardcode vào App.
- **Backend**: Vercel serverless trong `api/` — `ai.ts` (proxy Gemini/Groq, giấu key), `optimize.ts` (vòng tối ưu), `run.ts` (HTTP API + MCP server chạy app Prompt Graph bằng API key; `/api/mcp` rewrite về `/api/run?mode=mcp` trong `vercel.json`, MCP qua `@modelcontextprotocol/sdk` stateless — spec `docs/superpowers/specs/2026-11-19-graph-export-api-mcp-skill-design.md`; app xuất bản lưu sẵn `promptTemplate`/`variables`/`model` vì server không compile graph). Mỗi function **tự chứa** (không import file helper cục bộ — Vercel không bundle). Auth bằng Firebase ID token.
- **Firebase**: Auth (Google) + Firestore. Collections: templates, projects, rules, skills, workspaces, personas, bookmarks, healthSuites, sharedApps, suggestionModels, appFeedback, apiKeys — tất cả owner-only trừ template/sharedApp có phần public; `appFeedback` do người dùng Shared App tạo, chỉ chủ app đọc; `apiKeys/{sha256}` chủ tạo/thu hồi, `usage` chỉ server ghi.

## Quy ước (QUAN TRỌNG)

- **Thông báo**: `toast()` / `toast.success|error|info` từ `components/common/Toaster.tsx` (KHÔNG `alert()`).
- **Xác nhận**: `await confirmDialog({message,danger?,confirmText?})` từ `components/common/ConfirmDialog.tsx` (KHÔNG `window.confirm`).
- **Tên model AI**: chỉ khai báo ở `src/config/models.ts` — KHÔNG hardcode chuỗi model.
- **Màu/theme**: dùng token ngữ nghĩa (`bg-surface/panel/glass`, `text-ink/muted/faint`, `border-line`) — tự đổi light/dark. `src/index.css` có lớp override `!important` remap các utility slate/white theo theme; tránh dựa vào `bg-slate-*` cho bề mặt cố định.
- **Kính (glassmorphism)**: bề mặt kính dùng utility `glass-1` (card) · `glass-2` (sidebar/header/tab bar) · `glass-3` (modal/toast/drawer) kèm `border border-glass-edge` — KHÔNG tự ghép `bg-*/NN backdrop-blur-*`. Lớp nền màu `glass-ambient` đặt một lần ở App; tab muốn thấy nền thì đừng phủ nền đặc ở thẻ gốc. Không làm kính cho ô nhập/vùng soạn thảo và canvas Prompt Graph.
- **AI service**: `src/services/aiService.ts` — mọi hàm nhận `systemInstruction`. Persona chèn bằng `withPersona()`. Đa số hàm có fallback Gemini→Groq.

## Kiểm thử & CI

- `npm run lint` (tsc) · `npm test` (vitest) · `npm run build` (vite). Tests trong `src/__tests__/`.
- **`api/` bị loại khỏi tsconfig** → type-check riêng: `npx tsc --noEmit --skipLibCheck --moduleResolution bundler --module esnext --target es2020 --types node api/*.ts`.
- CI (`.github/workflows/ci.yml`) chạy cả 4 bước trên mỗi push/PR.
- Ưu tiên tách hàm THUẦN ra `src/utils/` hoặc service để unit-test được.

## Deploy

Xem `DEPLOY.md`. Tóm tắt: frontend+api → Vercel (`git push`); rules → `firebase deploy --only firestore:rules` (bắt buộc khi đổi collection); env `GEMINI_API_KEY`/`GROQ_API_KEY` đặt ở Vercel rồi **redeploy**.

## Nợ kỹ thuật còn lại

Tách God-component (RulesSkillsView, ConfigsView — đã chuyển vào `components/library/` nhưng chưa chia nhỏ; aiService — ProjectChainTab đã xong ở v3), TanStack Query, i18n, a11y toàn site, lịch health-check tự động (Vercel Cron), node AI biến đổi cho Prompt Graph (v3.1 — xem mục 11 của spec `docs/superpowers/specs/2026-07-04-project-chain-v3-prompt-graph-design.md`).
